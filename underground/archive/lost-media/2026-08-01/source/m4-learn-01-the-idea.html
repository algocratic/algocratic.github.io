Module 04 · Reading

Until now your programs have run in a straight line. This is where that ends — and where the diamonds you drew in Module 2 become something the machine can run.

Every statement in your programs so far has executed, top to bottom, every time. Change the input and the numbers changed — but the path through the program never did.

A program that makes decisions can take one path today and a different path tomorrow, depending on what it finds when it runs. This is called selection. It is the first of the two ideas that separate a calculator from a program. The second is repetition, and it is the next reading.

When you finish this reading you will be able to:

  • Write an if statement that runs a block only when a condition is true
  • Name the four parts of an if statement and say what each one does
  • Explain why both paths of a decision come back together

The idea in one picture

A decision is a question with a yes-branch and a no-branch. That is all it ever is, no matter how complicated the code looks.

In words: the program reaches a question. If the answer is yes, it does the thing. If the answer is no, it skips the thing. Either way it arrives at the same next step and keeps going.

Both paths come back together. Whatever the program decides, it continues afterward. A decision changes what happens for a moment. It does not end the program or start a new one.

The condition must be answerable yes or no. Not “how much.” Not “which one.” Just true or false. C++ has a type for exactly this — bool — holding two values and no others. Every condition you write, however long, collapses to a single bool before the program acts on it.

The smallest program that decides

Here is a complete C++ program that makes one decision. Read it before you run it.

// Program 4-1: The smallest complete decision.
#include <iostream>
using namespace std;

int main()
{
    int temperature = 38;

    cout << "Checking the freezer..." << endl;

    if (temperature > 32)
    {
        cout << "Warning: everything is melting." << endl;
    }

    cout << "Check complete." << endl;

    return 0;
}

Compile it and run it. Three lines come back:

Checking the freezer...
Warning: everything is melting.
Check complete.

Strip away the freezer and the shape underneath never changes:

if (condition)
{
    statements that run only when the condition is true
}

Four parts:

  1. The keyword if.
  2. A condition in parentheses. Required, always.
  3. A block in braces. Those statements run only when the condition is true.
  4. No semicolon after the closing parenthesis. See the caution below.

Caution

Most students who lose an hour to this module lose it to one semicolon. Writing if (temperature > 32); ends the if statement right there. The block below it then runs no matter what the temperature is.

Your compiler will warn you about this, and the warning says so in plain English. You will meet it in the next reading but one.

Before you move on

Open Program 4-1, change temperature to 20, rebuild, and run it again. Two lines print instead of three.

Do that now. It takes fifteen seconds, and it makes the idea stick in a way that reading about it does not.
