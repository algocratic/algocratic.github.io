Why Those Strata

Rule 4 requires every artifact to declare what year it thinks it is. Interactive site surfaces were built as Media/2026 on the screen column — that is the stratum v0.2 defines for badge language on screen, and it is where the nav, cards and counters live. The orientation packet was built as Pelican/196X on the print column, because it is a document, not an app.

198X Terminal appears on every page, but only as a crack — a mono phosphor panel deliberately interrupting a lighter page, marked frotz. That is the system's prescribed use. It is worth noticing that the published site is currently terminal-flavored end to end, which v0.2 would treat as one stratum applied everywhere. See open question 2.

The Yardstick

Judge fidelity against the five rules, condensed:

  • 0 · Produced artifacts outrank speculation. Shipped badges and print are canon; digital conforms.
  • 1 · Five typefaces, five jobs. Orbitron display, Saira Condensed labels, IBM Plex Sans body, IBM Plex Mono metadata, Bangers underground-only.
  • 2 · Screen ≠ print, both are real. Declare a substrate column and stay in it. Never average the two.
  • 3 · Pattern accretion. pattern(N) = pattern(N−1) at 30% + motif(N) at 90%. The badge remembers where you started.
  • 4 · Declare your stratum. 1968 Comix · 196X Pelican · 198X Terminal · 2026 Media. Never mixed except deliberately, at the cracks.

Plus the standing prohibitions the current site breaks: no emoji, no gradients, no stock icon sets, effectively no motion. The samples strip the emoji from the nav and console logs, drop the scanline and blink animations, and redraw the ASCII hierarchy diagram as flat geometric SVG.

What We Need Decided

01 Replace or coexist? The repo already contains Algocratic Futures Design System/ — the earlier navy / gold / Michroma identity — and static/portal-shell.css imports it on line 1, so all 22 shell pages inherit its tokens. Both systems define --link, --surface-page and --text-body with different values. They cannot both feed the shell. A GO means picking one.
02 Is the front door Media or Terminal? The published site is uniformly 198X-terminal-flavored. v0.2 says terminal is one stratum, used at the cracks. These samples take v0.2 at its word. If terminal-everywhere is the intended identity, that is a legitimate answer — but it should be an explicit choice, not an inheritance.
03 How does shared chrome get shared? The af-system-header block is hand-copied into 22 pages, and the site has no build step. Rolling out any system across all of them means a build step or a JS include. Worth deciding before the rollout, not during.

Known Gaps

  • Fonts are proxies. v0.2 itself names Orbitron as the web proxy for an unconfirmed production display face. No font binaries were provided; the tokens import from Google Fonts, which is a third-party runtime dependency the current site does not have.
  • The print column is incomplete. INFRARED, GREEN and BLUE print values are extrapolated (◇) pending the designer's swatch export. INDIGO, VIOLET, ULTRAVIOLET and GRAY have no print value at all — the orientation packet shows those as absences rather than borrowing the screen value.
  • BLUE+ accretion patterns are canonically [REDACTED] and were never drawn, so bands above GREEN have no pattern strip.
  • Vendored subset. static/design-system/ carries only tokens, styles.css and assets. The kit's React components, UI kits, slides and guideline cards were left out; the samples are plain HTML and CSS with no runtime.
  • One upstream fix is demonstrated but not applied. The published portal.html routes through stale website/-prefixed paths; the sample uses the corrected paths. The original file is untouched.
Out of character

Nothing here is a commitment. If the answer is no-go, delete the branch and the published site is exactly as it was. If the answer is go, preview/preview.css is the starting point — it is written entirely against v0.2 tokens with no new hex values, and is meant to graduate into static/ alongside portal-shell.css.
